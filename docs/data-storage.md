# Хранение и совместимость данных

Описание текущего кода 0.2.1. Источник: BookRepository, AtomicTextFile, ReaderPreferences, MainActivity и ReaderActivity. Приложение использует приватные файлы Android и SharedPreferences; общей транзакции между ними нет.

## Библиотека

Корень относительно приватного каталога приложения:

```text
files/books/library.json
files/books/<uuid>.epub
files/books/<uuid>.part          # незавершённая подготовка
files/books/index-*.part        # незавершённая запись индекса
cache/import*.part
cache/download*.part
cache/fb2*.fb2
```

`library.json` — JSON-массив без поля версии схемы:

```json
[
  {
    "id": "example-uuid",
    "title": "Название",
    "author": "Автор",
    "path": "/data/user/0/net.flibustareader/files/books/example-uuid.epub",
    "format": "FB2"
  }
]
```

`id`, `title`, `path`, `format` читаются как обязательные поля; отсутствующий author допустим. `path` хранится абсолютным; не заменяй его относительным без перехода для существующей библиотеки. `format` — исходный формат, готовый файл всегда EPUB. Это пример схемы, а не файл для импорта.

При чтении библиотеки строки с отсутствующим файлом фильтруются, сам индекс при этом не переписывается. Повреждённый JSON не заменяется автоматически пустой библиотекой; нельзя объявлять такое восстановление реализованным.

## Порядок записи и восстановления

1. Вход загружается/копируется во временный cache-файл с ограничением размера.
2. EPUB копируется или FB2 конвертируется в `files/books/<uuid>.part`.
3. После проверки отмены файл перемещается в `<uuid>.epub` с ATOMIC_MOVE.
4. Запись добавляется в индекс через AtomicTextFile. Новая книга помещается первой.
5. При обычном исключении результат подготовки удаляется; временные файлы очищаются в finally.

AtomicTextFile использует блокировку по canonical path внутри JVM-процесса, временный файл в том же каталоге и замену индекса. При неподдерживаемом атомарном перемещении индекса есть fallback на REPLACE_EXISTING. Для перемещения EPUB такого fallback сейчас нет. Это не межпроцессная блокировка и не обещание устойчивости ко всем сбоям питания.

BookRepository один раз на canonical directory за процесс читает индекс и удаляет `.part` и `.epub`, путь которых отсутствует в индексе. Окно между публикацией EPUB и записью индекса оставляет неиндексированную книгу; следующий запуск очищает её. Очистка не рассматривает cache-каталог как библиотеку.

Удаление книги сначала меняет индекс, затем удаляет файл и position/bookmark. `lastBook` при этом прямо не очищается; главный экран ищет его только среди доступных книг.

## SharedPreferences

Файл: `shared_prefs/reader.xml`. Это XML, управляемый Android SharedPreferences; не редактируй его вручную в рабочем профиле.

| Ключ | Тип / значение | Назначение |
| --- | --- | --- |
| `catalog`, `downloads` | String, HTTPS origin | Раздельные источники; по умолчанию flibusta.is |
| `lastBook` | String, id книги | Предложение продолжить чтение |
| `position:<id>` | String, Readium Locator JSON | Последняя позиция книги |
| `bookmark:<id>` | String, Readium Locator JSON | Одна закладка; отсутствие ключа означает её отсутствие |
| `readerColor` | String: WHITE/SEPIA/GRAY/BLACK | Цветовая схема, по умолчанию SEPIA |
| `readerFont` | String: BOOK/SANS/MONO | Системное семейство, по умолчанию BOOK |
| `fontSize` | Float, default 1.1, диапазон 0.7–2.5 | Масштаб шрифта |
| `lineHeight` | Float, default 1.5, диапазон 1.1–2.2 | Межстрочный интервал |
| `pageMargins` | Float, default 1.2, диапазон 0.3–2.5 | Поля Readium |
| `scroll` | Boolean, default false | Прокрутка вместо постраничного режима |
| `systemBrightness` | Boolean, default true | Использовать системную яркость |
| `brightness` | Float, default 0.65, диапазон 0.05–1.0 | Яркость окна читалки |
| `hudClock`, `hudProgress`, `hudBattery` | Boolean, default true | Видимость индикаторов |
| `theme` | Legacy String: DARK/LIGHT | Fallback при чтении старой темы; новый save его не записывает |

Неизвестные color/font получают fallback. Числа нормализуются, non-finite получают default. Некорректный Locator не должен интерпретироваться как процент; его чтение защищено runCatching. Формат принадлежит Readium, а не собственной схеме страницы приложения.

Пример структуры Locator (не полный перечень полей):

```json
{"href":"content.xhtml","type":"application/xhtml+xml","locations":{"progression":0.25}}
```

При сохранении используется `Locator.toJSON()`, при чтении — `Locator.fromJSON()`. Сохраняй дополнительные поля Readium, нужные для восстановления текстового якоря. Изменение типографики может немного изменить progression при сохранённом текстовом месте.

## Состояние каталога

CatalogState/ViewModel сохраняет книги, вкладку, запрос, режим авторов, текущую ленту и историю при повороте. MainActivity Bundle содержит `tab` (Int), `query` (String), `authors` (Boolean), `address` (String), `history` (список адресов).

Bundle относится к восстановлению Android task после уничтожения процесса, не к постоянным настройкам. Он не хранит полные ленты. `am kill` фонового процесса с возвратом в сохранённую task отличается от force-stop и нового запуска через launcher.

## Правила изменений и проверка

- При переименовании ключей/полей опиши переход старого значения, default и момент записи; не сбрасывай данные ради новой схемы.
- При изменении путей, id, очистки или порядка операций проверь готовые книги, индекс, Locator и существующие закладки на старом профиле тестового эмулятора.
- Не удаляй приложение перед проверкой обновления: `adb install -r` сохраняет профиль, uninstall/clear его уничтожают.
- AtomicTextFileTest проверяет индекс на JVM; reader-regression сравнивает индекс, SHA-256 книг и сохранённые данные чтения при очистке искусственных остатков.
- Этот сценарий не доказывает корректность реального убийства процесса во время импорта. Перечень непроверенных ситуаций — в [project-status.md](project-status.md).

В manifest `allowBackup=false`, правила исключают данные из cloud backup и device transfer. Синхронизации/экспорта пользовательской библиотеки сейчас нет. Изменение applicationId или подписи APK требует отдельного решения о доступе к прежним данным.
